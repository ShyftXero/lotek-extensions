{# Scribble rich-text editor partial (WS4 Phase A). Mounts the SHARED kit reporting editor (lotek_kit/static/reporting-editor.js, ext#212) for one content block of one finding: debounced autosave (POST/GET .../findings//blocks/, see scribble/autosave_api.py), lightweight polling presence ("X is editing", see scribble/collab/presence.py), inline image paste/drop -> artifact upload, and {{VARIABLE}} chip insertion. The editor is NOT scribble's any more — one canonical copy lives in the kit and every extension that authors report text mounts that. It is served by whichever host registered `lotek_kit.flask_assets.ensure_registered(app)` (core does, at /_kit), which is what makes `url_for('lotek_kit.static', …)` below resolve. Scribble's own standalone test harness has no core, so `scribble.testing.register_kit_assets_shim()` stands one up — see that function. Required context: finding — an EngagementFinding (needs .id and .content_json; a dict-like with those keys works too, e.g. from a fixture). block — str, the content-block name (see scribble/content/schema.py DEFAULT_BLOCKS: "description" | "remediation" | "details", or a template-defined block). Optional context: editor_user — str, attributed to this viewer's presence heartbeats. Falls back client-side to a random per-tab anonymous id (sessionStorage) when the host hasn't wired up auth yet. Usage from a page owned by another workstream (e.g. WS3's finding editor page): {% include "scribble/_editor.html" %} with `finding` and `block` already in the template context (e.g. via `{% with %}` or a render_template kwarg). `scribble_api_prefix` / `scribble_variable_keys` are injected automatically once the driver wires `scribble.autosave_api.register(api_bp, bp)` into the mount path (scribble/__init__.py); until then this partial degrades to the "/scribble/api" default and an empty variable list. NOTE ON `data-api-base`: the kit editor has NO default apiBase (P1 deliberately dropped the `/scribble/api` one so the primitive carries no scribble coupling). Every scribble surface that mounts it therefore MUST emit data-api-base, or autosave and image upload POST to a relative "/artifacts".
