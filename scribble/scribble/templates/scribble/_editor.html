{# Scribble rich-text editor partial (WS4 Phase A). Mounts scribble/static/editor.js for one content block of one finding: debounced autosave (POST/GET .../findings//blocks/, see scribble/autosave_api.py), lightweight polling presence ("X is editing", see scribble/collab/presence.py), inline image paste/drop -> artifact upload, and {{VARIABLE}} chip insertion. Required context: finding — an EngagementFinding (needs .id and .content_json; a dict-like with those keys works too, e.g. from a fixture). block — str, the content-block name (see scribble/content/schema.py DEFAULT_BLOCKS: "description" | "remediation" | "details", or a template-defined block). Optional context: editor_user — str, attributed to this viewer's presence heartbeats. Falls back client-side to a random per-tab anonymous id (sessionStorage) when the host hasn't wired up auth yet. Usage from a page owned by another workstream (e.g. WS3's finding editor page): {% include "scribble/_editor.html" %} with `finding` and `block` already in the template context (e.g. via `{% with %}` or a render_template kwarg). `scribble_api_prefix` / `scribble_variable_keys` are injected automatically once the driver wires `scribble.autosave_api.register(api_bp, bp)` into the mount path (scribble/__init__.py); until then this partial degrades to the "/scribble/api" default and an empty variable list. NOTE ON STYLING: scribble/static/scribble.css is a shared/frozen file this workstream doesn't own, so new editor-only classes (fr-editor-*) are scoped here rather than added there; the base look (.card, .btn, .pill, .muted) is reused straight from scribble.css's existing tokens. #} {% set _doc = (finding.content_json or {}).get(block) %} {% if not _doc %}{% set _doc = {"type": "doc", "content": []} %}{% endif %}
